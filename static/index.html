      Видалення даних

      Часткове: DELETE … WHERE у Citus + delete_by_query в Elasticsearch + скидання кешу Redis. Місце на диску після DELETE не зменшується — рядки лише позначаються мертвими; VACUUM дозволяє використати це місце повторно, VACUUM FULL повертає його ОС (але блокує таблицю). Повне: TRUNCATE — місце звільняється одразу.

      З консолі docker compose exec app python -m tools.data_admin delete --body mars --year-to 1990 docker compose exec app python -m tools.data_admin delete-all --yes docker compose exec app python -m tools.data_admin vacuum [--full] docker compose exec citus-coordinator psql -U space -c "TRUNCATE missions"

      Демонстрація: відключення шарда без втрати даних

      1. Увімкніть запис (вкладка «Навантаження», напр. 2000 рядків/с) і натисніть
      2. Вимкніть вузол: docker compose stop citus-worker-2 Запис у БД не вдається — пачки лишаються в буфері генератора й повторюються (див. журнал і «У буфері»). Пошук на вкладці «Пошук» працює далі: Elasticsearch — окремий вузол.
      3. Через хвилину-дві поверніть вузол: docker compose start citus-worker-2 Дані вузла лежать на його томі (citus_worker2) і повертаються разом із ним; буфер дописується.
      4. Коли «У буфері» = 0, натисніть Очікувано = рядків у знімку + записано після знімка − видалено після знімка; фактично — count(*).

      Те саме одним скриптом: ./scripts/outage_demo.sh citus-worker-2 60
